# ADR-013: 출석 체크(QR) 설계

## 배경

회원이 헬스장에 들어올 때 출석을 남긴다.
단순해 보이지만 **헬스장마다 QR의 역할이 완전히 다르다.** → [[도메인 지식#7. 출석]]

```
형식적 스캔형   데스크가 있고 QR은 기록용. 안 찍어도 들어갈 수 있다
출입 통제형     QR을 찍어야 문이 열린다. 주로 24시 무인 헬스장
```

이 차이가 나머지 결정을 전부 좌우한다.
출입 통제형에서는 **막는 판단이 곧 회원을 문 앞에 세우는 일**이기 때문이다.

---

## 결정 1: QR은 30초 만료의 별도 단기 토큰

회원 ID를 그대로 QR에 넣으면 캡처 한 번으로 무한 재사용된다.

```json
{ "sub": "userId", "gymId": "uuid", "type": "ATTENDANCE", "exp": ... }
```

- **30초 만료** — 캡처해서 남에게 보내도 도착하면 이미 죽어 있다
- **`type` 필드** — 일반 Access Token과 용도를 분리한다

> **`type` 검증을 빠뜨리면 이 설계 전체가 무의미해진다.**
> Access Token을 QR로 만들어 제출하면 그대로 출석이 된다.
> 서명도 유효하고 `sub`도 있으니 검증을 통과한다.
> 만료 30초는 **`type` 검증이 있을 때만** 의미가 있다.

### 선택하지 않은 안

**회원 카드 번호를 QR로 고정 발급.** 만료가 없어 캡처 후 공유가 자유롭다.
헬스장 매출과 직결되는 문제라(한 명이 끊고 여럿이 이용) 채택하지 않았다.

## 결정 2: 재출입은 유예 시간으로 처리한다

출입 통제형에서 실제로 발생하는 상황이다.

```
19:00  입장
19:20  흡연하러 나감
19:25  재입장  ← 이게 "두 번째 입장"이면 하루 1회 제한에 걸린다
```

`Gym`에 설정 두 개를 둔다.

```
Gym
  + dailyEntryLimit       INT  nullable    하루 입장 횟수. null이면 무제한
  + reentryGraceMinutes   INT  DEFAULT 0   이 시간 안의 재스캔은 같은 입장
```

```
reentryGraceMinutes = 0     형식적 스캔형. 매 스캔이 새 입장
reentryGraceMinutes = 30    출입 통제형. 30분 안이면 재입장으로 인정
```

> **on/off 플래그를 따로 두지 않는다.** `0`이 곧 "사용 안 함"이다.
> 불리언을 추가하면 `enabled: false, minutes: 30` 같은 **모순된 조합**이 저장될 수 있고,
> 그때 어느 쪽이 진실인지 코드가 판단해야 한다.

### 재입장도 행으로 남긴다

```
Attendance
  + isReentry  BOOLEAN  DEFAULT false
```

```
08:10  홍길동  isReentry=false   ← 입장 1회로 카운트
08:35  홍길동  isReentry=true    ← 카운트 안 함. 로그는 남음
19:20  홍길동  isReentry=false   ← 입장 2회
```

무인 24시 헬스장은 **사고 발생 시 누가 언제 안에 있었는지**가 필요하다.
컬럼 하나로 로그를 온전히 남기면서 횟수는 정확히 셀 수 있다.

## 결정 3: 퇴실은 만들지 않는다

퇴실 스캔 기능은 대부분의 회원이 사용하지 않는다. 그냥 나간다.
**동작하지 않는 기능이 있으면 재실 인원이 틀린 채로 표시되어 없느니만 못하다.**

입장 이벤트만 쌓는다. `입장 → 입장 → 입장`이 정상이다.

> **"확장 가능성을 열어둔다"는 것은 미리 만들어두는 것이 아니라 막지 않는 것이다.**
> 지금 `type: ENTRY | EXIT` enum을 만들면 값이 하나뿐인 enum이 생기고,
> 다음 사람이 "왜 EXIT를 안 쓰지?"에서 막힌다.
> `MembershipStatus.SUSPENDED`가 정확히 그 사례였다. → #22
>
> 나중에 필요해지면 `exitedAt`을 nullable로 붙이거나 행을 나누면 된다.
> **지금 아무것도 하지 않는 것이 가장 열려 있는 상태다.**

## 결정 4: 홀딩 중에는 입장을 막는다

**초안에서 뒤집힌 결정이다.**

ADR-011 작성 시점에는 "회원이 왔다는 건 홀딩이 끝났다는 뜻이니 자동 종료하자"고 적었다.
[[향후 과제]]에도 트리거와 함께 등록했으나, **도메인 확인 결과 틀린 판단이었다.**

| | 자동 종료 | 입장 차단 |
|---|----------|----------|
| 홀딩의 주체 | 시스템이 회원 대신 결정 | 회원이 신청하고 회원이 철회 |
| 오작동 시 | 회원권 기간이 깎이고 되돌릴 수 없다 | 문 앞에서 한 번 막힌다 |
| 잘못 찍었을 때 | 조용히 홀딩이 끝나 있다 | 알아차린다 |

**홀딩은 회원이 신청한 것이다.** 시스템이 임의로 종료하면
회원 동의 없이 회원권 기간을 깎는 것이 된다.
짐을 가지러 잠깐 들렀거나 실수로 찍었을 수도 있다.

"데스크가 해제를 깜빡한다"는 원래 문제는 `GET /holds/ending-today`로 이미 대응하고 있고,
그것은 **사람이 확인하고 사람이 누르는** 구조다. 자동 종료는 그 원칙을 깬다.

```
현재 휴회중인 회원입니다. 휴회를 철회한 후 이용해주세요
```

## 결정 5: 검증 순서

```
1. 토큰 서명·만료          → 401 QR_TOKEN_EXPIRED
2. type === 'ATTENDANCE'   → 401 INVALID_TOKEN_TYPE
3. gymId 일치              → 403 TENANT_MISMATCH
4. 재출입 유예 안?         → 기록만. isReentry=true. 이하 검사 건너뜀
5. 홀딩 중?                → 403 MEMBERSHIP_ON_HOLD
6. 유효한 회원권 없음?     → 403 NO_ACTIVE_MEMBERSHIP
7. 오늘 입장 횟수 초과?    → 409 DAILY_ENTRY_LIMIT_EXCEEDED
```

> **4번이 5·6·7보다 먼저인 것이 핵심이다.**
> 흡연하고 돌아온 회원을 "오늘 횟수를 다 썼다"고 막으면 안 된다.
> 유예 시간 안의 재스캔은 **이미 통과한 입장의 연장**이므로 다시 검사할 이유가 없다.

| 상황 | 안내 문구 |
|------|----------|
| 홀딩 중 | 현재 휴회중인 회원입니다. 휴회를 철회한 후 이용해주세요 |
| 회원권 없음 | 이용 가능한 회원권이 없습니다. 데스크에 문의해주세요 |
| 횟수 초과 | 오늘 입장 가능 횟수를 초과했습니다. 문제가 있으면 헬스장에 문의해주세요 |

**문구가 스펙이다.** 출입 통제형에서는 이 문장이 회원이 보는 유일한 화면이다.
"권한이 없습니다" 같은 문구는 회원이 무엇을 해야 할지 알려주지 않는다.

## 결정 6: 출입구 화면에는 마스킹된 이름만 보낸다

```
이*규 회원님 반갑습니다
회원권이 87일 후에 만료됩니다
```

문 앞 화면은 지나가는 사람에게도 보인다. 풀네임은 개인정보다.

**마스킹은 서버에서 한다.** 클라이언트가 가리면 서버는 풀네임을 보내는 것이므로
네트워크를 보면 그대로 노출된다. 가린 의미가 없다.

그러면 데스크에서도 `이*규`로 보이는 문제가 생기는데, **엔드포인트를 나눠서 푼다.**

```
POST /attendance/check-in   maskedName만    출입구 단말용
GET  /users?...             풀네임          데스크 응대용
```

> **용도가 다른 화면을 하나의 응답으로 만족시키려 하면 항상 더 넓은 쪽에 맞춰진다.**
> 그러면 보안은 좁은 쪽 기준으로 무너진다.

마스킹 규칙:

```
이준규     → 이*규      가운데
남궁민수   → 남**수     가운데 전부
김철       → 김*        2글자는 뒤를
```

## 결과

**얻는 것**

- 형식적 스캔형과 출입 통제형을 **같은 코드로** 지원한다. 차이는 헬스장 설정값뿐이다
- 재입장 때문에 회원이 문 앞에서 막히는 일이 없다
- 출입 로그가 온전히 남아 사고 시 추적할 수 있다

**감수하는 것**

- 재실 인원을 알 수 없다. 퇴실을 기록하지 않기 때문이다
- `reentryGraceMinutes`를 길게 잡으면 그 시간 안에는 다른 사람이 찍어도 통과한다.
  QR 토큰 자체가 30초 만료라 실제 악용은 어렵지만, **유예 시간은 짧을수록 안전하다**

- 출석 데이터 보관 정책 및 파티셔닝
- 퇴실 기록
- 회원 정보에 주소·생년월일 추가 (도메인 지식 1장)
