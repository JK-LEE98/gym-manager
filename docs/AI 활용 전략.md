# AI 활용 전략 — gym-manager

## 개요

이 프로젝트는 단순히 AI에게 코드를 생성시키는 방식이 아니라,
Claude를 **멘토 / 동업자 / 도구** 세 가지 역할로 구분하여 프로젝트 전 과정에 통합한다.
설계부터 구현, 문서화, 리뷰까지 AI와 협업한 전 과정을 기록한다.

---

## Claude 역할 정의

### 멘토 (Mentor)
- 기술 결정 시 트레이드오프 설명 요청
- Spring Boot 경험을 NestJS로 연결하는 개념 브리지 역할
- 더 나은 방향이 있을 때 현재 접근법에 대한 비판적 피드백

### 동업자 (Co-founder)
- 기능 명세, DB 모델링, 아키텍처 설계를 함께 결정
- 단순 이행이 아닌 능동적 의견 제시
- 포트폴리오/면접 관점에서 어필 전략도 함께 고려

### 도구 (Tool)
- NestJS 모듈 코드 생성
- Obsidian 문서 직접 작성 및 업데이트 (파일 접근 권한 활용)
- 커밋 메시지 초안 생성
- 코드 보안/성능 자체 리뷰

## 활용한 Claude 기능

### 1. 파일 시스템 직접 접근
Cowork 모드에서 Claude가 로컬 파일에 직접 접근하여 Obsidian 문서를 생성/수정한다.
단순 텍스트 출력이 아닌, 실제 파일로 관리되므로 문서와 코드가 항상 동기화된다.

```
Claude → Read/Write/Edit 도구 → Obsidian Vault md 파일 직접 수정
```

### 2. CLAUDE.md 기반 컨텍스트 유지
프로젝트 루트의 `CLAUDE.md`를 통해 Cowork, Claude Code CLI 어떤 환경에서도
동일한 컨벤션과 역할 정의로 일관된 협업이 가능하다.

### 2-1. 컨텍스트 계층화 (ADR-007)

`CLAUDE.md`는 매 요청마다 로드되므로 무한정 키울 수 없다.
실제로 파일이 388줄까지 커졌을 때 **환경변수 값이 실제 `.env`와 어긋난 사례**가 발생했다.

정보를 3계층으로 분리하고 단일 출처 원칙(SSOT)을 적용했다.

| 계층 | 위치 | 담는 것 |
|------|------|--------|
| 항상 로드 | `CLAUDE.md` | 항상 참이고 어기면 손해가 큰 규칙만 |
| 필요시 읽기 | Obsidian | 상세 맥락, 설계 근거, 이력 |
| 사실의 출처 | 실제 파일 | `.env.example`, `package.json`, 코드 |

핵심 원칙은 **"실행 가능한 형태로 이미 존재하는 정보를 문서에 복사하지 않는다"** 이다.
결과적으로 **388줄 → 206줄(바이트 기준 31% 감소)** 로 축소하면서 정보 손실은 없었다.
정리 과정에서 Git 컨벤션과 개발 워크플로우가 중복 서술되어 있던 구조적 결함도 함께 발견해 통합했다.

> 토큰 비용(약 4,000토큰, 컨텍스트의 2%)보다
> **주의 분산**과 **정합성 붕괴**가 더 실질적인 비용이라는 판단이 근거다.

### 3. ADR (Architecture Decision Record) 공동 작성
중요한 기술 결정마다 Claude와 함께 ADR을 작성한다.
단순 선택이 아니라 배경 → 선택지 → 결정 → 이유의 구조로 기록하여
면접에서 "왜 이 기술을 선택했나요?"에 대한 근거 자료로 활용한다.

### 4. 선제적 리뷰 (Proactive Review)
코드 작성 후 Claude가 자율적으로 아래 항목을 점검한다:
- 보안 취약점 (JWT 노출, 권한 누락, SQL Injection 가능성)
- N+1 쿼리 문제
- 트랜잭션 누락
- 기술 부채 가능성

### 5. Spring ↔ NestJS 개념 브리지
Spring Boot 경험자가 NestJS를 익히는 과정에서
Claude가 두 프레임워크의 개념을 1:1 매핑하여 학습 속도를 높였다.

## 협업 워크플로우

```
1. 기능 설계 논의 (Cowork 채팅)
        ↓
2. 설계 확정 → Obsidian 문서 업데이트 (Claude가 직접 파일 수정)
        ↓
3. ADR 작성 (중요 결정 시)
        ↓
4. 코드 구현 (Claude 생성 + 개발자 검토)
        ↓
5. 보안/성능 리뷰 (Claude 자체 점검)
        ↓
6. 커밋 (Claude 메시지 초안 제시)
        ↓
7. 트러블슈팅 발생 시 → Obsidian 트러블슈팅.md 기록
```
